# 扩展岗位方向与候选（2026-10-05）

> 本页服务于 2026 年的学习方向调研。个人计划是 2027 年 7 月补贴到账后才开始投递；届时须重新确认职位、薪酬和城市。以下“候选”表示职责与现有经历有连接点，不表示职位届时仍开放或保证可获得面试。

## 调整后的找岗方式

原先“四类各 10 个”的配额让能源后端、充电桩 Java 两类限制了整个调研。今后以**杭州 Java 服务端开发**为主池，按真实职责而非岗位名称搜索：

1. **经验最直接：**能源数字化、设备接入、工业物联网、智慧园区、充电运营平台的 Java 服务端。
2. **能力可迁移：**企业软件／SaaS、制造业业务平台、物流供应链、支付与交易、医疗信息化等 Java 后端；看重接口、数据、消息、模块交付和线上排障。
3. **周边备选：**宁波、嘉兴、绍兴、湖州等城市中确有明确职责的岗位，单独标注，不与杭州岗位混写。

先积累能读到职责和要求的不同 JD，优先形成 10～15 份核心样本，再继续扩充；40 份作为后续调研规模参考，**不再强制四类各 10 份**。同一职位只计一次。卡片或搜索列表仅提供摘要时，标“列表线索”，不纳入技术要求频次。主要工作若为长期驻场实施、销售、硬件嵌入式、前端或算法，仍不作为目标岗位。3～5 年可作冲刺，但应由真实项目范围支撑职责，任职时间保持真实。

薪酬在这轮不设机械阈值；明显低于当前待遇或职责过重的职位只作学习样本。最终比较税前年包、公积金、强度和发展空间，不能将当前税后月收入与招聘税前月薪直接比较。

## 从这些 JD 得出的准备顺序

1. **先做好一个可讲清的设备接入与数据链路案例。**说明协议解析、连接与状态、异常恢复、消息处理和线上排障，优先对应艾瓦、威胜、正元等方向。
2. **争取一个完整业务模块。**需求、表与接口设计、权限／告警／任务、单测、发布和日志分析完整走一遍，支撑通用 Java 后端与 SaaS 岗位。
3. **补数据库和服务端基础。**MySQL 索引／事务、Redis、Kafka、Java 并发与网络、Spring Boot/Cloud、Linux 排障，比再增加一个狭窄行业标签更有用。
4. **具体机会再判断薪酬和工作形态。**当前收入是税后，招聘广告多写税前；同时确认开发与实施比例、值守、出差、导师和代码评审。

本轮只完成方向扩展与候选初筛。列表摘要职位不计入 JD 技术频次；2027 年投递前重新采集在招岗位。
