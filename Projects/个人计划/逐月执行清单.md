# 逐月执行清单

> [!summary] 这份文档回答什么问题
> 「这个月、这周，我**具体**要做什么。」
> 战略判断（为什么走这个方向、什么时候跳槽）见 [[职业发展规划]]；学习内容和原理见 [[技术学习计划]]。
> 本页只写**动作、产出、完成标志**，不重复论证。

> [!tip] 三条使用规则
> 1. 每个月只认「产出」。没有产出就算未完成，不看学了几个小时。
> 2. 时间不够时按第 0 节砍任务，**不要顺延整月**。
> 3. 状态只有四种：未开始 / 进行中 / 暂停 / 已完成。

## 0. 时间不够时怎么办

一句话原则：**任何一周，最低保留「弄懂一条小链路 + 做一个验证」**，其余全部可以砍。

| 情况 | 砍掉 | 保留 |
|---|---|---|
| 加班周（只剩 2～3 小时） | 基础补课、文档整理 | 读代码 + 手写一次报文测试 |
| 出差 / 上线周 | 几乎全部 | 只在手机上翻 JD、把问题记下来 |
| 连续两周没进展 | 暂停学习 | 花 15 分钟复盘：是时间不够，还是方向不对 |

## 2. 第 1 个月：摸底月

> [!important] 这个月不学新技术
> 目标是把三件事问清楚：**市场要什么、公司给不给机会、这条链路到底怎么走。**
> 它不占用学习配额，做完才进入主线。
> 本月的**可勾选待办**见 [[2026-10]]（按月拆分，逐项打勾）。

### 第 1 周：JD 反向拆解（约 3～4 小时）

1. 打开 BOSS 直聘 / 拉勾 / 猎聘，城市选杭州，用这 4 个关键词各搜一遍：
   - `Java 后端`
   - `Java 物联网`
   - `能源 后端`
   - `充电桩 Java`
2. 每个关键词**复制 10 个 JD**（公司、岗位、薪资、经验年限、学历要求、技术要求全文）到 [[JD 拆解与岗位池]]，共 40 份。
3. 把技术要求拆成词逐个计数。重点盯这些词出现了几次：
   `Java 基础`、`Spring Boot`、`MySQL 索引/事务`、`Redis`、`Kafka/RocketMQ`、`并发/JUC`、`JVM`、`Netty`、`Linux`、`Docker/K8s`、`微服务`、`MQTT`、`Modbus/104 等电力协议`
4. 统计出**出现 ≥5 次的 TOP 10 要求**。
5. 逐条对照自己，标成：已具备 / 半具备 / 不具备。

**完成标志**：[[JD 拆解与岗位池]] 里有 40 份 JD 原始记录 + TOP10 表 + 自己的三档标注。

### 第 2 周：岗位池 + 问清机会（约 3 小时）

**A. 岗位池（1 小时）**

- 统计 40 份 JD 里能源/IoT 相关有几份、占比多少
- 把公司按 [[职业发展规划]] 第 9.3 节的三层分类填好，**每层至少 3 家**

**B. 问清机会（2 小时，需要主动约人）**

找直属 leader，或那位工作 8 年的同事，直接问这三个问题（可以照着念）：

1. 「我能不能参与一个从需求到上线的完整模块？大概什么时间点会有这种机会？」
2. 「团队现在有代码审查吗？设计和方案可以找谁看？」
3. 「我现在负责的协议开发，接下来还有哪些要接？后面有没有需要我主导的部分？」

把**原话**记下来，写回 [[职业发展规划]] 第 7 节。

**完成标志**：拿到明确答复（能 / 不能 / 大概什么时候），而不是「再看看」。

### 第 3 周：确认资产 + 选定一条链路（约 5 小时）

- 确认：协议文档、脱敏报文、测试环境，哪些你能**自主使用**？拿不到就自己造脱敏样例。
- 选定**一条**你最熟的协议 + 一种消息（心跳 或 充电状态上报）。
- 开始读代码，按这个顺序找每一站在哪：
  **入口 Handler → 消息边界（分包/粘包在哪处理）→ 字段解析与校验 → 设备与连接的关联 → 业务处理 → 消息队列/缓存/数据库**
- 边读边把看不懂的写成问题清单，**先记下来，不要停下来查**。

**完成标志**：能说出这条链路上每一站对应的类名或文件名。

### 第 4 周：画图 + D1 检查（约 4 小时）

- 画出第一版链路图（手画拍照也行），标注线程和组件。
- 从问题清单里挑出**最影响主链路理解的 5 个问题**。
- 做 D1 检查：

- [ ] 40 份 JD 与 TOP10 缺口清单
- [ ] 公司分层清单，每层 ≥3 家在招
- [ ] 组织内机会的明确答复（非「再看看」）
- [ ] 现有资产可用范围明确
- [ ] 链路图第一版完成

全部打勾 → 进入第 2 个月。有未完成 → 第 2 个月第一周补上，**学习主线不推迟**。

## 3. 第 2 个月：把一条链路吃透

目标：从「我知道它大概怎么走」变成「我能预测它的行为」。

1. **写报文测试（本月核心产出）**
   - 正常报文 → 逐个核对关键字段
   - 分段输入：把一条报文拆成 2～3 次发
   - 连续输入：两条报文粘在一起发
   - 错误长度、错误校验位
   - 每种情况都记录**实际解码结果**
2. **主动复现 1 个异常**，优先选「重复消息」或「重连后旧连接如何处理」
   - 记录三件事：实际行为 / 预期行为 / 原因
3. **请同事审一次**链路图或关键实现，记录他的反馈
4. **补基础**：只补这个月卡住你的那个点，不要系统性铺开

| 卡在哪 | 补什么 |
|---|---|
| 分段、粘包看不懂 | TCP 字节流、Netty `ByteToMessageDecoder` |
| 多线程改状态看不懂 | Java 内存模型、线程安全 |
| 连接管理看不懂 | Netty Channel 生命周期、引用计数 |

**完成标志**：一页总结——「已经理解什么 / 发现了什么 / 还缺什么」。

## 4. 第 3 个月：选一个真实问题 + 开始试水

### 4.1 选问题（上半月）

从下面这些里选**一个真实存在的**（不是想象出来的）：

- 厂家报文差异难排查
- 掉线状态更新不及时
- 数据推送失败缺少补偿
- 重复消息导致重复处理
- 新协议只能靠现场试验，缺少回放验证

选定后**先做现状记录，不要急着改代码**：

- **现象**：什么时候发生、多频繁（有日志就贴日志）
- **影响面**：影响多少台设备 / 哪个环节
- **现有处理方式**：现在怎么应付的，不足在哪

### 4.2 开始试水面试（下半月）

> [!warning] 这个月就投，不要等到第 6 个月
> 面试是最便宜、最准确的能力校准器。晚了半年，你会用错误的自我判断准备半年。

- 挑 **1～2 家你不打算去的公司**投递（小公司、外包、不感兴趣的方向都行）
- 目的只有一个：拿到真实反馈
- 面完**当天**记录：被问到什么、哪些答不上来、对方最关注什么
- 把这些直接更新进 [[JD 拆解与岗位池]] 的能力缺口清单

**完成标志**：问题现状记录 + 至少 1 次面试反馈记录。

## 5. 第 4 个月：做出改进

1. 设计方案——**至少写一个被否决的方案和否决理由**
2. 实现：AI 可以帮你写，但每一段你都要能解释
3. 验证：用第 2 个月那套测试方法证明**行为真的变了**，不是只证明「能跑」
4. 整理成**改进案例文档 v1**，按 [[职业发展规划]] 第 9.1 节的六个字段写：
   背景与规模 / 我的职责边界 / 技术难点 / 方案取舍 / 证据 / 如果重做

**完成标志**：案例文档 v1 存在，里面的数字都是实测的——没有实测的写「未测量」，不要估算。

## 6. 第 5 个月：补完整业务模块

### 情况 A：拿到了完整模块

自己走完整流程：**需求确认 → 表与接口设计 → 实现 → 权限与数据边界 → 测试 → 上线 → 效果观察**。
每一步都留痕：设计文档、评审记录、上线 checklist。

### 情况 B：没拿到（第 1 个月的答复就是「不能」）

不等机会，走备选路径：

- 主动在评审会或周会上**认领**一个小模块，而不是等分配
- 挑一个现有的零散任务，**人为闭环**：自己补上需求确认、设计、测试、上线记录
- 把「远程指导客户设备上线」整理成**排查手册 / FAQ**——这份东西本身就是可展示的产出

优先争取的小模块：**设备告警记录、第三方推送任务管理、设备接入配置**。

**完成标志**：能拿出「需求→设计→测试→上线」这条链的记录，不管模块多小。

## 7. 第 6 个月：收口 + 出简历 + D2

1. 完成模块闭环（或备选路径的闭环记录）
2. **写简历 v1**——不要拖到第 12 个月
   - 把前几个月的成果压缩成 3～4 条带数字的要点
   - 准备 **2 分钟**和 **5 分钟**两个版本的项目自述
   - 对外材料全部脱敏：不写客户名称、不写公司数据与业务机密
3. **D2 检查**：

- [ ] 能独立解释一条 IoT 链路并复现异常
- [ ] 一个可靠性改进有证据（案例文档 v1）
- [ ] 完整模块闭环记录（或已走备选路径且有产出）
- [ ] 简历 v1 完成

全部达成 → 开始少量投递（5～10 家，其中 1～2 家用于校准）。
未达成 → **延长 3 个月，只补最短板的那一项，其余暂停**，不整体顺延。

## 8. 第 7～9 个月：案例文档 + 基础补齐

- 把两个案例**逐个**写成一页文档——先写完第一个，不要两篇一起写
- 每写完一篇，做一次「三层追问」自测：
  **为什么这么设计 / 边界与异常情况 / 有没有替代方案**
- 八股按第 1 个月统计出的 **TOP10 高频要求**逐项过，优先补「不具备」那几项
- 算法题：每周固定 2～3 题，不要突击

**完成标志**：第一个案例文档能脱稿讲 5 分钟，并且白板上能画出链路。

## 9. 第 10～12 个月：面试冲刺 + D3

1. 两个案例文档成稿
2. 投递按 [[职业发展规划]] 第 9.3 节分层推进：**第一层主攻（内推优先）→ 第二层并行**，第三层放到 D3 之后
3. 每次面试当天记录反馈，每周汇总一次，更新缺口清单
4. **D3 检查**（第 12 个月末）：

- [ ] 两个案例文档成稿
- [ ] 能白板画链路并应对三层追问
- [ ] 面试反馈显示缺口可控
- [ ] 达成 → 正式投递；未达成 → **写明留任理由与新期限，不接受「继续延长」作为结论**

## 10. 每周固定动作

| 次数 | 时长 | 内容 |
|---|---|---|
| 3 次 | 30～45 分钟 | 读项目代码，顺手补一个卡住你的基础点 |
| 1 次 | 60～90 分钟 | 连续做实验：写测试、复现异常、验证改进 |
| 1 次 | 15 分钟 | 记录：这周产出了什么、卡在哪、下周唯一重点 |

合计约 5～7 小时。忙碌周按第 0 节砍，**不补课、不叠加**。
